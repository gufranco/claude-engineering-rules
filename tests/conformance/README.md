# Mutation-method-blocker conformance suite

Test262-style behavior verification for the hook. Each `.test.ts` file has
YAML frontmatter declaring the expected detector verdict, and
[`test_conformance.py`](test_conformance.py) runs the hook against each case
and asserts the verdict matches. Collection fails when no case is found.

## Verdict values

| Verdict | Hook exit code | Meaning |
|---------|---------------|---------|
| `allow` | 0 | Code is allowed: no mutation flagged, file out of scope, or suppressed |
| `block` | 2 | Code contains a mutation the hook must block |

Any other verdict fails the case.

## Frontmatter format

```yaml
---
description: short one-line description of the case
verdict: block
detector: array.
payload: edit
file: /repo/src/business/example.ts
---
const items = []
items.push(1)
```

| Field | Required | Description |
|-------|----------|-------------|
| `description` | yes | Human-readable summary used in test output |
| `verdict` | yes | Expected outcome: allow or block |
| `detector` | optional | Substring of the detector code that must appear in stderr when verdict=block |
| `payload` | optional | `write` (default) or `edit` |
| `file` | optional | Defaults to `/repo/src/business/conformance.ts` |

## Adding cases

Cases are generated by [`_generate_cases.py`](_generate_cases.py), which writes
`cases/<category>/<NNN>-<label>-<verdict>.test.ts` or, for some groups,
`cases/<category>/<group>_<NNN>-<label>-<verdict>.test.ts`. The generator
overwrites files but never deletes them, so remove a case file by hand when
its generator entry goes away.

1. Add the case to the matching `*_CASES` tuple in the `_cases_*.py` module
   beside the generator, built with `block` or `allow` from
   [`_case_model.py`](_case_model.py).
2. Run `.venv/bin/python tests/conformance/_generate_cases.py`.
3. Run `.venv/bin/pytest tests/conformance`.

Every case must pass; there is no partial-pass threshold.
